Behaviour, security & S1 gate compliance · web-variant note
  • No enumeration, ever. The request always shows the same "if an account matches…" confirmation — the flow never reveals whether a number/email is registered. Mirrors the GA-007 no-enumeration rule.
  • No shame. Forgetting a password is normal: copy is warm and practical ("Tell us the number or email…"), the mismatch is "these don't match yet," and success never scolds. No "you failed," no red-fill alarm.
  • Rate-limit stated up front. A calm note ("once every 60 seconds") sets the expectation before a resend is even attempted, and the sent step runs a plain-text countdown that becomes an active "Resend code" link at zero.
  • Strength as signal, not gate-keeping. A four-segment token bar + text label + a short live requirements checklist — never colour alone, never a wall of rules. Show/hide is a real [44pt] <button>.
  • Session safety on reset. Saving a new password signs the account out of other devices; the success banner states this plainly as protection, and offers a "not you?" route to /help/account-recovery.
  • Real anchors, real controls. Request /forgot-password, sent /forgot-password/sent, set-new /reset-password, login /login, help /help/account-recovery. Toggle, eye and submit are real <button>s; navigation actions are standalone anchors. No href="#", no button-in-anchor. [44pt] throughout.
  • On-palette, dignified, bilingual. Every colour is a var() token; no ornament; EN/UR parity; copy is plain descriptive with no invented stats.
  • Web variant (/forgot-password · /reset-password, SPA). Same steps in a centred ~440px card: an emailed magic-link opens /reset-password?token=… straight to set-new-password; an expired/used token renders a calm "this link has expired — request a new one" with a live re-request, keeping the no-dead-end rule.
