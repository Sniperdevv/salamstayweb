Screen — Referral programme, host side (HA-069)

The invite surface in the host tab, at /host/referral. SalamStay ships one referral programme — GA-110 — and this screen is that programme seen from hosting, not a second one: the same flat PKR 1,500 thank-you credit for both sides once an invited friend completes their first stay, the same personal link salamstay.pk/r/aqibg, the same three invites with the same states and the same 18 Jun 2026 credit date. The halal framing is reused verbatim — "A flat thank-you — never interest" — a one-time credit, never a percentage, never tied to what anyone spends (DESIGN §10.3, SEO §5). A quiet line states outright that this is the same link as the travelling account, so the two surfaces can never drift apart. The one question a host would actually ask and the product cannot yet answer — what if the person I invite becomes a host? — renders as a labelled template slot with a Not set yet chip (the HA-067 convention), parked for founder sign-off, rather than an invented figure. "How it works" is a plain numbered explainer, not a journey stepper (§7.6a). Host chrome. Panels: full screen (light) · link copied (dark) · no invites yet (light) · اردو / RTL.

Nothing here is a new programme, and the screen says so. The figure, the link, the trigger, the three lifecycle states and the 18 Jun 2026 credit date are all carried across from shipped GA-110 — a host and a traveller looking at the same account must never see two different numbers. The "one programme, one link" row is the mechanism that keeps them honest: it links straight to /account/referral, so drift would be visible in one tap. The halal framing is stated, never sold — a plain role="note" banner in the muted info register, no percentage language, no cashback, no riba-adjacent wording. The {host_referral_reward} slot is the one honest gap: a host will ask what happens if their friend starts hosting, and rather than answering with a number nobody has agreed, the row names the question, admits it isn't decided, and holds the space the build will fill. "How it works" uses static circles with no connecting progress line and no current state — it is an explainer, not the 4-step booking stepper (§7.6a).
