GA-003 — Permissions primer (mobile app)

A calm rationale sheet shown before the OS permission dialog — so the guest understands why we ask, and the one-shot native prompt isn't wasted. One bottom sheet per permission (location, notifications, camera): plain specific reasons, "Not now" always at equal weight, an honest "the system will ask next" note, and a no-nagging denied-state path back to Settings. Never an intrusive interstitial over content — it's requested in context (location only on "Stays near me").

Rules, states & rationale
  • Primer before prompt. The rationale sheet always precedes the one-shot OS dialog, so the native prompt isn't spent on a confused user; every sheet ends with "the system will ask next."
  • In context, ask-late. Location is requested only on "Stays near me," camera only at CNIC verify / add-a-photo, notifications after first meaningful action — never a cold-launch grab, never an intrusive interstitial over content (SEO §6).
  • "Not now" equal weight. The decline is the same size and prominence as Allow — no dimmed micro-link, no dark pattern (§10.7, §10.9 optionality is explicit).
  • Prayer quiet-hours. Framed as a plain notification benefit on the neutral bg.raised surface — a courtesy, never a brand-green endorsement or a religious widget (§10.1/§10.3).
  • Denied state guidance. A calm path to Settings with the exact route plus a keep-moving primary ("Search by city") — no nagging, no re-prompt loop, no dead end.
  • Fallbacks named. Camera denial → gallery upload; location denial → type a city. Declining any permission never blocks browsing or booking.
  • Motion / a11y. Sheet rises from the bottom edge and dismisses the same way (spatial, reversible); reduced-motion → cross-fade. Each sheet is a focus-trapped role="dialog"; every control ≥44pt with a localized Urdu name.
