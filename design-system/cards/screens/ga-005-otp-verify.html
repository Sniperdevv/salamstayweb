Behaviour, channel & S1 gate compliance · web-variant note
  • WhatsApp-first, SMS fallback (ARCH). The header states the channel plainly ("Sent on WhatsApp") with a one-tap "Get it by SMS instead" to /verify-phone?channel=sms. Channel choice respects the PECA consent captured at sign-up.
  • §14 segmented input, done right. Six boxes, one digit each, auto-advance / auto-backspace, numeric keypad, paste-fills-all, native one-time-code autofill; the group is one labelled field, each box announces "digit n of 6".
  • Resend is a behaviour constant, not a motion token. "Resend in 0:28" is a plain text countdown (banner variant, inputs §17) that becomes an active "Resend code" link at zero — no animation, no spinner.
  • No dead ends on failure. A wrong code recolours the boxes (border + role="alert" message, never colour alone), shows the attempts left, and names two next steps: recheck the message or resend. Expiry/too-many-attempts escalate to /help/verification.
  • Success is a status, then a route. A brief border.success flash + role="status" banner, then forward to GA-009; back is retired so there's no re-entry into a verified step.
  • On-palette, dignified copy. Every colour is a var() token; the WhatsApp mark is monochrome interactive.primary, not brand-green; no ornament. Copy is neutral descriptive — no invented stats or social proof.
  • Web variant (/verify-email · /verify-phone, SPA). Same six boxes centred in a ~440px card; desktop supports paste + arrow-key nav between boxes; the countdown/resend and "Change number"/"Get help" links are identical; email verification swaps the header target and channel note to email.
