Behaviour, security & S1 gate compliance · web-variant note
  • Handoff is honest, not fake progress. The interstitial is a role="status" live region shown only while the provider/OS sheet is open; it always carries a real Cancel back to /signup, and the ring is transform-only (stops under reduced-motion).
  • Never silently merge. When a provider email matches an existing account, the guest is asked to link — two named identities, an explicit action, and a "sign in another way" escape to /login. Consent is required; the existing verified state is shown so nothing feels at risk.
  • Social does not bypass PK phone identity. A first Google/Apple sign-up still captures a +92 number and routes to OTP GA-005; the CNIC line reuses the GA-004 just-in-time framing (verify at booking, not now).
  • Cancelled / error is calm. An outlined role="alert" notice (icon + text, never a red fill), "nothing was saved," and three live exits — retry, switch provider, or mobile-number sign-up. No shame, no dead end.
  • Real anchors, real controls. Providers /auth/google · /auth/apple, sign-up /signup, login /login, verification /legal/verification, Terms/Privacy. The link and send actions are real <button>s; recovery actions are standalone anchors (no button-in-anchor). [44pt] throughout.
  • On-palette, dignified, bilingual. Every colour is a var() token; monochrome provider marks; no ornament; EN/UR parity; copy is registry-verbatim or plain descriptive — no invented stats or social proof.
  • Web variant (/auth/callback, SPA). Same four states as an in-page card on the auth chrome: the handoff is the redirect-return spinner, linking and first-sign-up render identically, and the cancelled state reads the provider error/state params to show the same calm return with a CSRF-safe retry.
